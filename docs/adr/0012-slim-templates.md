# 0012: Slim AGENTS.md / CLAUDE.md and agent prompts down to the skills

- **Status:** Superseded by [0014](0014-skills-only-agent-instructions.md)
- **Date:** 2026-11-25

## Context

ADR 0010 moved the Dispatch workflow into three agent skills and ADR 0011
ships them in the binary, but `dispatch init` still scaffolded the old
`AGENTS.md` / `CLAUDE.md`: about 450 lines each, holding a second full copy of
what the skills say. Two copies drift apart, and the skills' fixes (the actor
rules, `workspace adopt`, `commit add`) never reached the templates. Agents
started by `agent create` were pointed at `AGENTS.md`, not at the skills
(GitHub issue #23).

## Decision

**Slim templates.** The repository-root `AGENTS.md` and `CLAUDE.md`, which
`nob` embeds and `init` scaffolds, are now identical and about 60 lines:

- the Critical Rules (the six original rules plus the actor rule the skills
  added, so a session that never loads a skill still records actors
  correctly) and the "storage file is an implementation detail" paragraph;
- how to find the workflow directory;
- a table naming `dispatch-plan`, `dispatch-work` and `dispatch-board` by job;
- the fallback when the skills are missing: `dispatch skills list`,
  `dispatch skills install` from the workflow directory, and
  `dispatch skills install --global` for sessions started inside the product
  repository, where Codex and opencode stop their search at the product
  repository's git root (ADR 0011). With no way to install them, the agent asks the user
  rather than working from memory.

The files no longer differ (the old copies differed only in naming
themselves and in the actor of an example), so one text serves every runner.

**Coverage.** Every section of the old template was checked against the
skills before it was cut; nothing had to move, because ADR 0010 already
placed each one:

| Old template section | Now in |
| --- | --- |
| Intro, workflow-directory layout | template (short form) and every skill's "Find The Workflow Directory" |
| Critical Rules | template, and repeated in every skill |
| Instruction Visibility | `dispatch-work` |
| Core Commands | `dispatch-board` `references/commands.md` (current CLI) |
| How Dispatch Works | `dispatch-plan` |
| Session Startup | `dispatch-work` |
| Selecting Work (work selection) | `dispatch-work` |
| Selecting Work (readiness rules, `--no-review`) | `dispatch-board` "Readying Tasks", `dispatch-plan` "Leave tasks proposed" |
| Task Execution Protocol | `dispatch-work` |
| Commit Discipline | `dispatch-work` |
| Workspaces And Parallel Agent Safety | `dispatch-work` (plus Orca / `workspace adopt`) |
| Planning Work (group reuse, issues, example) | `dispatch-plan` |
| Agent Identity And Workspace Setup | `dispatch-work` |
| Running A Task Sequence In One Workspace | `dispatch-work` |
| Executing A User-Named Task | `dispatch-work` |
| Failure Handling | `dispatch-work` |

`tests/check_skills.sh` now also reads the templates: every
`dispatch <command> [<subcommand>]` in their code must exist in
`dispatch --help`, and each template must name all three skills. Template
mentions do not count towards the skills' command coverage.

**Agent prompts.** `agent create` (and `normalize` when it regenerates) writes
`<name>-PROMPT.md` with the agent ID block as before, a new
`## Dispatch Skills` section (`dispatch-work` as the main skill,
`dispatch-plan` / `dispatch-board` when the user asks for planning or board
work, `dispatch skills install` if they are missing), and an Actor Usage
section aligned with ADR 0010: the agent's own name for `workspace create`,
`start`, `finish` and `commit add`; `--actor user` for `ready`, `group ready`
and `review` the user decided; its own name for `review` only when assigned as
reviewer. The old prompt listed `review --actor <agent>` as routine, which
contradicted the skills. The command in `run.sh` is unchanged.

**Refreshing old prompts.** `normalize` already regenerated prompts that
lacked `## Agent ID` or still contained `## Repository Instructions From
AGENTS.md` (the oldest prompts, which copied `AGENTS.md` in under that
heading). Both conditions stay, and a prompt without the
`## Dispatch Skills` heading is now stale too, so every prompt written before
this change is regenerated by the next `normalize`. `doctor` reports the same
condition as `agent_prompt_outdated` (fix `run dispatch normalize`) instead of
a plain "prompt exists" ok.

**Existing boards.** `doctor` warns `instructions_outdated` for `AGENTS.md`
and `CLAUDE.md` when the file contains the heading
`## Task Execution Protocol`. Every version of the old template had that
heading (checked through the history of both files), the slim template does
not, and it is specific enough not to appear in unrelated instructions. A
whole-file hash would miss boards that edited their copy, and the old title
`# Dispatch Agent Instructions` is the line people are most likely to keep.
The fix hint is `dispatch skills install`, then shortening the file to the
slim template; doctor never rewrites the file because it may hold the
person's own additions, and `init` still never overwrites an existing file.
The README's "Upgrading Older Boards" section walks through it.

## Consequences

- One copy of the workflow: the skills. The templates carry only rules that
  must hold even before a skill loads.
- This repository's own `AGENTS.md` / `CLAUDE.md` are those templates, so
  agents working on Dispatch itself get the short version. They need the
  skills too: `dispatch skills install --global`, which works without a
  board, or `dispatch skills install` from a board's workflow directory.
- A session whose runner cannot see the skills, and that cannot install them,
  has only the critical rules and is told to ask the user.
- `tests/golden/cli/` holds the scaffolded templates and two generated
  prompts; changing either needs `UPDATE_GOLDENS=1 tests/run_cli_tests.sh`.
  `tests/fixtures/legacy-AGENTS.md` keeps the last long template for the
  doctor test.
